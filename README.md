# Avela

Плагин WordPress: предупреждения перед чтением статьи, ручной публичный анонс и серверная выдача полного материала после подтверждения. Версия 0.1.1, WordPress 6.4+, PHP 7.4+.

## Использование

1. Поместите каталог `avela` в `wp-content/plugins` и активируйте плагин.
2. В меню **Предупреждения** доступны три начальных шаблона: стандартное 18+, грубая лексика, чувствительный материал. Можно создавать свои, менять пояснение, заголовок, кнопки и внутренний адрес выхода.
3. В редакторе записи или страницы найдите блок **Avela · Предупреждение перед чтением**. Выберите один шаблон и заполните **Публичный анонс**. Сохраните запись. Метабокс работает в классическом редакторе и Gutenberg.
4. Ссылки «До подтверждения» и «После подтверждения» открывают подписанный предпросмотр для редактора. Они используют сохранённые настройки.
5. Общие параметры доступны в **Предупреждения → Настройки и диагностика**: подтверждение одной статьи или одного шаблона, срок, повтор при изменениях, кнопка сброса, индексация изображений.

У существующих статей предупреждения автоматически не включаются. Пустой анонс не заменяется началом полного текста. Заголовок всегда публичный: редактор должен сделать его безопасным. Корзина и удаление шаблона не открывают связанные статьи; недоступный шаблон заменяется стандартным предупреждением.

## Доступ и хранение

До подтверждения HTML содержит только заголовок, анонс и форму. Исходный текст, изображения, видео и комментарии не помещаются в скрытый DOM. Подтверждение работает обычным POST без JavaScript, возвращает 303 на постоянный URL статьи. Форма связана с браузером, действием, актуальным предупреждением и сроком.

Подписанная HttpOnly-cookie `avela_grants` хранит до 12 последних принятых предупреждений; при достижении лимита 3800 байт старые записи вытесняются раньше. `avela_age` отдельно хранит до четырёх результатов прохождения возрастного порога. `avela_browser` нужна для защиты формы от межсайтовой отправки. Все три имеют SameSite=Lax, Secure на HTTPS, без записи каждого просмотра в БД. Подписи разделены по назначению, сайту и блогу. По умолчанию подтверждение действует только для одной статьи, в текущем сеансе, максимум 12 часов. Можно задать 1–720 часов. Изменение общих настроек сбрасывает принятие предупреждений. Изменение шаблона требует повторного принятия, если этот параметр включён; сами формы всегда должны соответствовать актуальному предупреждению. Кнопка «Скрыть материал» удаляет принятие предупреждения, сохраняя действующий результат возраста.

Версия 0.1.1 использует новые подписи: прежние подтверждения 0.1.0 необходимо пройти заново. Версия шаблона меняется при изменении условий, а не при повторном сохранении того же содержимого.

Нажатие кнопки означает **заявление о возрасте** (`self_declared`), а не документальную проверку. Дата рождения, документы и профиль пользователя не собираются.

Фильтруются стандартные представления WordPress:

- Основной HTML, архивы, поиск, автоматические выдержки, обложки, галереи и стандартные изображения вложений. Анонс и шаблон предупреждения не исполняют шорткоды.
- REST записей/страниц, включая `_embed`; закрытые поля и дополнительные REST-поля заменяются публичным набором. REST ограниченных медиа и комментариев закрывается; коллекции исключают их.
- RSS/Atom всегда содержат только анонс, даже с cookie подтверждения. Комментарии, их ленты и форма закрыты вместе со статьёй.
- Стандартный oEmbed; фильтры описаний, изображений, schema и image sitemap Yoast SEO/Rank Math. Наличие фильтров не означает проверенную совместимость со всеми версиями этих плагинов.
- Редактор с правом изменения статьи получает исходный материал в административных запросах и REST. Публичный просмотр редактором также требует подтверждения или подписанного предпросмотра.
- JSON медиатеки также соблюдает право редактирования статьи; остальные посетители проходят обычное подтверждение.

Произвольные конструкторы, сторонние API, GraphQL, печатные/AMP-версии и плагины, которые напрямую читают БД или собственные метаполя, требуют адаптеров. Отключение Avela прекращает фильтрацию; деактивация не удаляет настройки.

## Поиск и медиа

Постоянный URL, HTTP 200, заголовок и стандартный canonical сохраняются. Статьи остаются в стандартной XML Sitemap. Описание берётся из ручного анонса. Метка `rating=adult` включается отдельно у статьи и по умолчанию выключена.

При сохранении статьи собирается реестр медиа: обложка, прикреплённые файлы, блоки, вложенные/повторно используемые блоки, классические галереи и URL файлов, включая относительные URL, `srcset` и `poster`. Учитываются фактический URL вложения и responsive-размеры WordPress. Изменение размеров вложения обновляет затронутые статьи. Снятие ограничения с одной статьи сохраняет ограничения других владельцев файла. Сопоставление произвольных динамических шорткодов и внешних CDN требует адаптера.

Каждая статья хранит собственный производный реестр в метаданных. Он не может перезаписать реестр другой статьи. Ревизия источника обнаруживает устаревшую сборку той же статьи; пересборка не публикует пустой общий список. Источником ограничений остаётся выбранное предупреждение. Если реестр утрачен или ещё строится, комментарии остаются закрыты, публичные медиа временно скрываются и для uploads действуют консервативные правила robots. В админке появляется уведомление и доступна кнопка пересборки. При длительном конфликте допускается одна отложенная повторная попытка для конкретной статьи; постоянного обхода сайта нет.

Редактор получает предупреждение о файле, используемом также в открытой статье. Известные ограниченные файлы убираются из социальных метаданных и image sitemap открытых статей тоже; желательно использовать разные файлы для открытых и ограниченных материалов.

Для ограниченных изображений добавляются `noimageindex`, `max-image-preview:none` и правила виртуального `robots.txt`. Правила по началу имени охватывают размеры, оригинал и варианты WebP/AVIF, но могут затронуть соседние файлы с тем же началом имени. Ограничение URL действует во всех местах использования изображения. Правила добавляются во все существующие группы роботов, поскольку конкретная группа имеет приоритет перед `User-agent: *`.

Если есть физический `robots.txt`, перенесите правила из диагностики в него. Для внешнего домена медиа/CDN правила нужно разместить на том домене; диагностика показывает отдельные наборы. CDN, меняющий имена файлов, нужно подключить через `avela_restricted_media_urls`. Существующие поисковые копии исчезают после повторной обработки роботом.

**Прямые файлы по известному адресу остаются доступны.** Защищённая медиатека с авторизацией самого HTTP-ответа файла в эту версию не входит.

## Кеширование перед выпуском

Плагин выставляет `DONOTCACHEPAGE` и `Cache-Control: private, no-store` для публичных ответов, включая архивы и REST: их результат зависит от cookie. Условные запросы не получают 304 с повторным использованием старой версии ленты; валидаторы ETag/Last-Modified отключены для таких динамических ответов. При изменениях вызываются очистка WP Super Cache/W3 Total Cache/WP Rocket, событие LiteSpeed и `avela_purge_cache` для других интеграций.

**Кеш/CDN, отвечающий до загрузки плагина, необходимо отключить или настроить отдельно.** `advanced-cache.php` загружается раньше обычных плагинов. Уведомление в админке показывает обнаруженный ранний кеш. Отключите его средствами используемого кеша (включая `WP_CACHE`, если применимо), отключите общий HTML-кеш на CDN и очистите ранее созданные ответы. Внешние кеши не обнаруживаются автоматически.

Проверьте цепочку на реальном хосте: новый браузер → анонс; подтверждение → полный текст; другой новый браузер → снова анонс; REST и ленты → публичное представление. Продукционная инфраструктура и внешние CDN локальными тестами не проверены.

На `liliadna.local` уже существуют общий экран согласия темы Liliadna Fox и тестовый редирект `.htaccess`. Avela их не изменяет. Пока они включены, посетитель сначала проходит общий экран, затем предупреждение конкретной статьи; публичная доступность анонсов поисковикам зависит и от этих механизмов.

## Будущие провайдеры возраста

Адаптер реализует `Avela_Age_Provider::verify($post_id, array $input)` и регистрируется фильтром `avela_providers`. Фильтр `avela_required_provider` задаёт обязательный провайдер для статьи. Результат:

```php
[
    'status' => 'passed', // passed | failed | unknown
    'threshold' => 18,
    'method' => 'document_verified',
    'provider' => 'example',
    'checked_at' => time(),
    'expires_at' => time() + 3600,
]
```

Неизвестный/отрицательный ответ, некорректные типы полей, отсутствие обязательного провайдера и истёкший результат сохраняют ограничение; автоматической замены внешней проверки локальной кнопкой нет. Исключение провайдера возвращает общий 503 без раскрытия деталей. Сохраняются только шесть перечисленных полей, дополнительные данные профиля отбрасываются. Действующий результат возраста можно использовать при принятии другого предупреждения того же провайдера; само предупреждение нужно принять отдельно. Для асинхронных OAuth-провайдеров дополнительно потребуются собственный callback, защита state/PKCE и интерфейс начала проверки. VK и другие сервисы в этой версии не подключены.

Другие точки расширения: `avela_restricted_media_urls($urls, $post_id, $attachment_ids)` и действие `avela_purge_cache`.

## Проверки

Только на локальном тестовом WordPress с активным Avela:

```powershell
php tests/regression.php C:/OSPanel/home/liliadna.local --http
php tests/security.php C:/OSPanel/home/liliadna.local --http
```

Тесты создают временные записи, шаблоны, вложения без физических файлов и комментарии, затем удаляют их и восстанавливают настройки. Публикационные переходы намеренно обходятся, чтобы другие плагины не отправляли тестовые статьи во внешние сервисы. Для локальной темы тест проходит её существующую форму согласия. HTTP-проверки используют тестовую cookie редиректа `.htaccess`. Проверка редакторского REST создаёт отдельную краткую сессию существующего администратора и удаляет только её. Диагностические HTML сохраняются в игнорируемом `artifacts/`.

Аудит 0.1.1 воспроизводит потерю реестра, чередование сохранений разных статей и одной статьи, обход через `include`, относительные медиа, повреждённые формы, старые условные HTTP-запросы, разделение возраста/предупреждения, сбои провайдера и выдачу через REST/RSS/Atom/oEmbed/медиатеку. Локальная среда проверки: WordPress 7.1.3 и PHP 8.5. Продукционные кеш/CDN, сторонние конструкторы и матрица старых версий WordPress/PHP не проверены.
